##### 11.1 운영: 설비 선제 배치까지의 선행 시간

- v2.1은 2026년 경계 사건 8건 중 7건을 감시 단계로 중앙 21일(공식 발령일 기준 31일), 경보 단계로 중앙 14일(공식 발령일 기준 21일) 앞서 포착했다. 지속성은 2건이었다(표 6-4).[^c11-2]
- 상태 라벨(7.4절)에 따라 '지켜보기'(감시)에서는 채수 주 2회와 설비 준비 점검을, '경계 진입 예상 — 미리 대비'(경보)에서는 녹조제거설비 선제 배치와 정수장 고도처리 준비 요청을 권고한다. 감시를 비용이 낮은 조치에만 연결한 것은 2020~2025년 감시 규칙(q90) 알림 270회 중 109회가 헛경보였기 때문이다(6.4절).
- 대시보드는 지점을 상태 라벨 순위, 같은 순위 안에서는 경계 초과 확률 순으로 정렬하고, 설비 배치 우선순위는 단계(경보→감시→정상) 안에서 경계 초과 확률 순으로 정한다(7.5절). 예상은 공식 발령을 대체하지 않으며, 발령 판단에 앞서 대비할 시간과 근거를 준다.

##### 11.2 정책: 당일 발령 확대의 예측 가치

- 2026년 녹조계절관리제는 조류경보 당일 발령 지점을 낙동강 본류 4곳에서 7곳으로 넓히고, 나머지 21개소의 발령 기간을 단축한다(보도 기준, 6.12절·7.7절).[^c11-3]
- 같은 모델에서 기준일 당일 측정을 쓰면 경계 F1이 2025년 0.532에서 0.705로, CV 0.355에서 0.598로 높아진다. 2026년 감시 중앙 리드는 14일에서 21일로 길어지고, 경보 포착은 5건에서 7건으로 는다(표 6-11). 당일 결과 공개는 발령을 앞당길 뿐 아니라 7일 예측의 입력을 최신으로 만든다.
- 매일 05시(KST)에 자동 갱신되는 관제 상황판은 녹조 대응 체계에 필요한 '예측·조기경보 기능'의 원형이다(7.7절). 법안 통과나 기관 채택을 전제하지 않는다.

##### 11.3 확장: 조류경보제 다른 지점

- 입력은 모두 공개 자료다(조류경보제 조회서비스, 기상청 ASOS, K-water 댐·보 운영, WAMIS·DataON 수위, 2.2절). 다른 지점에는 지점별 설정(좌표·최근접 ASOS·수문 연결·수온 임계)을 더해야 하며, EXP-008은 이를 새로 정하고 전 지점 수집기를 더해 기존(v1) 피처 함수로 다른 지점 표본을 만들었다.
- EXP-008에서 조류경보제 조회서비스를 지점 목록 없이 조회해 82개 지점 51,714행(2012-01-03~2026-10-15)을 1분 만에 받았다. 우리 5지점 밖 77개 지점에도 같은 피처 함수로 표본 42,166행을 만들었다(5.8절 표 5-1의 R5).[^c11-4]
- 한계도 있다. 다른 지점의 수문 자료는 77곳 중 29곳(시설 운영자료 24곳, 상류 본댐만 5곳)에만 있다. 다른 지점 표본을 학습에 더해도 2025년 확인 구간에서 우리 5지점의 성능 이득은 없었다. 다른 지점에 적용할 때는 지점별로 다시 검증해야 한다.

##### 11.4 비용: 공공 자료와 무료 요금제

- 일일 운영 입력은 모두 공공 API 자료이며(2.2절), 학습·재현에 쓴 대회 번들도 원출처가 같은 공공 자료로 겹치는 구간의 값이 같다(2.3절·9.1절). 새 측정 장비가 필요 없다.
- 일일 운영은 GitHub Actions 예약 실행, Supabase 무료 플랜, Vercel Hobby 요금제로 돌린다. 수동으로 띄운 첫 성공 실행은 4분 만에 끝났다(새 측정이 없어 예측은 건너뜀, 8.2절). 모델은 동결본을 그대로 쓰고 매일 재학습하지 않는다.[^c11-5]
- 제출 결과 재현은 CPU만으로 약 20분(8코어 기준)이며 GPU가 필요 없다(9.2절).

## 확인·결정이 필요한 점

1. **'29개소 53지점'의 출처.** 공식 출처(보도자료·통계)가 있으면 알려 달라. 11.3 에 그 수치와 출처를 넣고 PDF·zip 을 다시 만들겠다. 지금은 저장소 기록(82개 지점, 당일 발령 7곳·나머지 21개소)만 썼다.
2. **모델자료 zip 안 폴더 이름.** zip 이름은 `AlgaeCast_모델자료_이재행` 이지만, 풀면 나오는 폴더는 예전 그대로 `AlgaeCast_녹조7일예측_이재행/` 이다.
   - 문서자료 읽어보기에 폴더 이름을 적어 두었고, '한 개의 폴더' 조건도 지킨다.
   - 맞추려면 빌더의 `PKG_NAME` 을 바꾸고 재빌드·재검증(약 1시간)이 필요하다.
3. **압축 해제 위치.** 깊은 폴더에 풀면 Windows 경로 길이 제한에 걸릴 수 있다. 재현용 `.venv` 는 경로가 더 길어진다. 패키지 README 에 '짧은 경로에 풀 것' 한 줄을 넣을지 결정이 필요하다(지금은 넣지 않았다).
