# 12. 통합관제 대시보드 개편 설계서 (T7-R)

> 착수 시점: T8(일일 자동화)·T9-b(제출 패키지·재현 검증) 완료 후.
> 목표: 도시통합관제센터·재난안전상황실·112 종합상황실의 **상황판(비디오월)** 형태로 바꾸고, 모든 문구를 **비전문가가 10초 안에 이해**할 수 있게 고친다.
> 기존 데이터·API·Supabase 스키마는 그대로 쓴다. 바뀌는 것은 화면 구성, 시각 언어, 문구뿐이다.

---

## 1. 콘셉트

**"녹조 통합관제센터 상황판"**

| 참고 대상 | 가져올 요소 |
|---|---|
| 도시통합관제센터(스마트시티) | 다크 네이비 배경, 격자형 멀티 패널, 지도 중심 배치, 실시간 시계 |
| 재난안전상황실 | 위험 단계 색체계, 상단 전체 상황 배너, 조치 사항 체크리스트 |
| 112 종합상황실 | 실시간 이벤트 로그(시간순 스크롤), 신규 상황 점멸 알림 |
| 기상청 특보 상황판 | 지역별 상태 타일, 향후 기상 티커 |

화면 하나로 상황 전체를 읽는다. 메인 상황판은 1920×1080에서 **스크롤 없이** 모든 정보가 보여야 한다.

### 3.1 영역별 명세

| 영역 | 내용 | 비고 |
|---|---|---|
| 상단바 | 시스템명, 상태 LED 3개(수집/예측/DB: model_runs 최신 status·시각으로 판정), 실시간 시계(초 단위, KST), 마지막·다음 갱신 | LED: 정상 초록, 지연(24h 초과) 노랑, 실패 빨강 |
| 상황 배너 | 단계별 지점 수 + 한 줄 요약(자동 생성) | 배경색 = 현재 최고 단계 색 |
| 지점 현황 | 타일 5개, 위험 순 정렬. 타일: 단계 색 띠, 지점명, 단계 이름, 현재 측정값, 7일 뒤 예상값, 가능성 막대, 추세 화살표 | 클릭 → 지점 상세 |
| 지도 | CartoDB Dark Matter 타일(출처 표기), 낙동강·금강 수계선 강조, 단계 색 마커, "대응 필요"는 펄스 애니메이션 | prefers-reduced-motion이면 점멸 끔 |
| 오늘의 조치 | 단계별 권고 문장을 체크리스트로(체크는 브라우저 로컬 저장, 공유 X) | 경보 → 주의 순 |
| 실시간 상황 기록 | 단계 변화, 새 측정 도착, 예측 갱신, 시스템 이벤트를 시간 역순 | 새 항목 3초 하이라이트 |
| 지점 모니터 | 5분할 패널, 각각 60일 측정 추이 + 1천/1만 기준선 + 7일 뒤 예상 점 | 관제실 CCTV 분할 화면 은유 |
| 향후 7일 날씨 | 대표 관측소 최고기온 스파크라인, 강수 예보 | 단기·중기 예보 데이터 |
| 성적표 띠 | 신뢰 근거 한 줄 | 클릭 → 성능 페이지 |

### 3.2 관제 기능
- **자동 갱신**: 5분마다 `router.refresh()`. 새 데이터가 들어오면 상단에 "새 정보" 토스트.
- **전체화면**: Fullscreen API 버튼.
- **순환 모드** `?kiosk=1`: 네비게이션 숨김, 30초마다 메인 → 지점 상세(위험 순) → 메인 순환. 비디오월 상시 표출용.
- **신규 경보 알림**: 마지막 방문 이후 단계가 올라간 지점은 타일 테두리 점멸 + 상황 기록 상단 고정. 경보음은 기본 꺼짐, 토글로 켬.
- **발표 모드**: 라이트·고대비 테마(프로젝터용). 토글 상태는 로컬 저장.

## 6. 시각 언어

### 6.1 색 토큰 (다크 기본)
| 토큰 | 값 | 용도 |
|---|---|---|
| bg | #0A1020 | 전체 배경 |
| panel | #111A2E | 패널 |
| panel-border | #1E2A44 | 패널 테두리 |
| text | #E6EDF7 | 본문 |
| text-dim | #8A9BB8 | 보조 |
| accent | #38BDF8 | 링크·선택 |
| safe | #22C55E | 안전 |
| watch | #FACC15 | 주의 관찰 |
| alert | #F97316 | 대응 필요 |
| severe | #EF4444 | 공식 경계 이상 실측 / 대발생 |
| line-obs | #E6EDF7 | 측정값 선 |
| band | #38BDF8 25% | 예상 범위 |

색만으로 구분하지 않는다: 단계마다 아이콘(● 안전, ▲ 주의, ◆ 대응 필요) + 텍스트 병기. 발표 모드는 같은 의미의 라이트 팔레트.

### 6.2 타이포
- Pretendard(본문), 숫자는 `tabular-nums`, 시계는 등폭 숫자.
- 상황판 최소 글자: 본문 16px, 타일 수치 32px, 상황 배너 22px. 3m 거리에서 읽히는 크기.

### 6.3 모션
- "대응 필요" 마커 펄스 2초 주기, 신규 상황 하이라이트 3초. 그 외 애니메이션 없음.
- `prefers-reduced-motion` 존중.

## 7. 문구 원칙

1. 화면에 영어 약어 금지: q50, q90, p_alert, tier, CQR, OOF, SHAP, F1, PR-AUC는 쉽게 보기에서 보이면 안 된다.
1-1. 예측값은 하나만 보인다(2026-10-23): 큰 숫자 '예상값' = 제출 모델 v2 점예측(`pred_cell_count`). 예상 범위(CQR q10~q90)와 넘을 가능성(분류기)은 함께 표시하고, v1 공유 분위 중앙값(q50)은 전문가 보기에만 둔다. 타일·지점 상세·모니터 5분할·지도 팝업·차트 점·추세 화살표·적중(✓/✗) 판정이 모두 같은 값을 쓴다. 예상값이 예상 범위 밖이면 값은 그대로 두고 '범위 밖 ⓘ'로 알린다.
1-2. 설명 문장 규칙(`copy.ts` `explainForecast`): 예상값 ≥ 1만이면 "예상값이 경계(1만)를 넘을 것으로 보입니다(가능성 n%)", 1만 미만인데 범위 위쪽이 1만 이상이면 "예상 범위 위쪽이 1만을 넘기 때문" 문장, 둘 다 아니고 가능성 ≥ 52%면 가능성이 높다는 문장, 그 밖은 낮다는 문장.
2. 숫자에는 항상 단위와 기준을 붙인다: "2.7만 개/mL (경계 기준 1만)".
3. 큰 수는 "약 2.7만"처럼 만 단위 반올림, 상세 툴팁에 정확한 값.
4. 확률은 "가능성 96%"로. "확률", "신뢰도" 대신.
5. 한 문장 40자 이내, 주어는 지점명.
6. 공식 발령 단계(실측)와 AI 예상 단계는 항상 구분해 표기: "공식 발령: 경계" / "AI 예상: 대응 필요".
7. 단정 금지: "넘습니다" 대신 "넘을 가능성이 높습니다".
8. 권고는 동사로 끝낸다: "배치하세요", "요청하세요".

## 8. 용어 바꾸기 표 (코드 내부명 → 화면 문구)

### 8.1 이유 문장 템플릿 (SHAP → 문장)
| 그룹·방향 | 문장 |
|---|---|
| ar + | 최근 녹조가 이미 많습니다 |
| ar − | 최근 녹조가 줄고 있습니다 |
| water + | 물 온도가 높은 날이 계속됐습니다 (25℃ 이상 {n}일) |
| water − | 물 온도가 내려가고 있습니다 |
| hydro + | 보·댐 방류가 적어 물이 고여 있습니다 |
| hydro − | 방류가 늘어 물이 잘 흐릅니다 |
| weather + | 한 달간 더웠고 비가 적었습니다 |
| weather − | 비가 와서 녹조가 씻겨 나갈 수 있습니다 |
| time_site + | 녹조가 많이 생기는 시기입니다 |

### 8.2 권고 문장 템플릿 (상태 라벨별, 2026-10-21 개정)
| 상태 라벨 | 문장 |
|---|---|
| 경계 진입 예상 | {지점}: 다음 주 측정에서 1만 개/mL를 넘을 가능성이 높습니다({p}%). 녹조제거설비를 미리 배치하고, 정수장에 고도처리 준비를 요청하세요. |
| 지켜보기 | {지점}: 경계 수준을 넘을 수도 있습니다. 채수를 주 2회로 늘리고 상황을 자주 확인하세요. |
| 경계 계속될 듯 | {지점}: 경계가 다음 주에도 계속될 가능성이 높습니다({p}%). 녹조제거설비 가동과 정수장 고도처리 등 현재 대응을 유지하세요. |
| 나아질 가능성 | {지점}: 녹조가 줄어들 가능성이 있습니다. 해제 판단에 대비해 채수를 유지하고 상황을 확인하세요. |
| 안전 | {지점}: 1주일 안에 큰 변화는 없을 것으로 보입니다. 평소대로 관리하세요. |

### 8.3 상황 배너 한 줄 요약 템플릿 (2026-10-21 개정)
- 상태 라벨 순위(8.4) 순으로 `{지점, 지점} {라벨}` 을 ` · ` 로 잇는다. 같은 라벨 안의 지점 구분자는 쉼표.
  예: "강정·고령 경계 진입 예상 · 해평 지켜보기 · 칠서, 물금·매리, 회남 경계 계속"
- 전부 안전: "전 지점 안전 · 다음 갱신 {시각}"
- 배너 색 = 가장 높은 순위 라벨의 색. 우측에 라벨별 지점 수.

### 8.4 상태 라벨 = 공식 발령(측정) × AI 예상 조합 (2026-10-21 추가)
타일·오늘의 조치·지도 범례·배너가 모두 이 체계를 쓴다. 정렬은 순위 → 같은 순위 안에서는 1만 넘을 가능성 내림차순. `web/src/lib/copy.ts` 의 `COMBO`/`comboOf` 가 단일 정의다.

| 순위 | 공식 발령 | AI 예상 | 라벨 | 아이콘·색 | 조치 방향 |
|---|---|---|---|---|---|
| 1 | 관심·없음 | 대응 필요 | 경계 진입 예상 — 미리 대비 | ◆ severe(#EF4444), 맥박·강조 테두리 | 설비 선제 배치·고도처리 준비 |
| 2 | 관심·없음 | 주의 관찰 | 지켜보기 | ▲ watch(#FACC15) | 채수 주 2회·설비 준비 점검 |
| 3 | 경계 이상 | 대응 필요 | 경계 계속될 듯 | ◆ alert(#F97316) | 현 대응 유지 |
| 4 | 경계 이상 | 주의 관찰·안전 | 나아질 가능성 — 해제 준비 | ▼ accent(#38BDF8) | 해제 대비 채수 유지 |
| 5 | 관심·없음 | 안전 | 안전 | ● safe(#22C55E) | 평소대로 |

AI 예상 단계(안전/주의 관찰/대응 필요)와 공식 발령(관심/경계/대발생)은 라벨 아래 줄에 항상 따로 적는다.
