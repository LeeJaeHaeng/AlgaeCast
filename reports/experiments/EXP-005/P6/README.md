## 1. 목적·설정

**지시(원문).** R5에서 수집한 지점 중 상류 댐 호소 지점의 최근 세포수 × 해당 댐 방류량을 하류 지점 피처로 연결한다.

**기준 모델.** C = v1 로그 앙상블(C1·C3·C2) + R2 상류 피처 5열 + R3 속별 구성원 cg 이다. 분위는 v1 동결 q90 이다. 이 실험은 분위를 바꾸지 않으므로 리드타임은 모든 구성에서 18/20 이다. 재현은 `harness2.c_pred(df, seed, extra)`(새 열은 C1·C3·C2·속별 구성원 모두에 들어감)로 한다. 하이퍼파라미터는 v1(`harness.v1_specs`) 그대로다.

### 1.3 피처(as_of = base_date 규칙)

하류 지점 s 의 연결 r 마다:
- c_r = 호소 조류 지점들의 obs_date ≤ as_of − lag_r 최근 유효 세포수다. 지점별 최근값의 최대이고, 경과일이 35 + lag 일을 넘으면 결측으로 둔다.
- q_r = [as_of − lag_r − 6, as_of − lag_r] 하천 방류 평균이다(유효 4일 이상).
- f_r = c_r · q_r 이다.

이를 연결 전체로 묶어 5열을 만든다. 연결이 없거나 유효 연결이 0 이면 모두 NaN 이다.

| 열 | 정의 | 지시 항목 |
|---|---|---|
| dam_cell_log | log10(Σf_r / Σq_r + 1), 방류 가중 세포수 | 최근 세포수 |
| dam_days | max_r(as_of − 사용한 측정일) | 경과일 |
| dam_q_log | log10(Σq_r + 1), 7일 평균 하천 방류 | 방류량 |
| dam_load_log | log10(Σf_r + 1), 세포수 × 방류량 플럭스 | 곱 |
| dam_contrib_log | log10(Σf_r / max(Q_down, 1) + 1), 하류 유량으로 희석한 기여 농도 | 곱(희석 보정) |

함수 `make_dam_features` 와 `link_state` 는 진입 직후 `features.base.cut_as_of(·, as_of)` 를 부르고, lag 이 있으면 as_of − lag 로 한 번 더 자른다. 가용률은 칠서·물금·매리·회남 행 100%, 해평·강정·고령 행 0%(CV·2025 모두)다.

- 탐색 판정은 `harness2.explore_check`(PREREG_FINAL 기준을 탐색 시드에 적용한 참고값)다. 선택 변형은 ΔCV +0.08·대조 +0.04 를 못 넘고, 2025 9~10월 rmse_log 도 C 보다 나쁘다(0.388 vs 0.374). 2025 r2_raw·rmse_log·F1·리드타임 비열등 조건은 통과했다.

- core4_lag0_all 과 core4_travel_all 의 대조군은 같은 열 수·같은 결측 위치라 난수까지 같아 결과가 같다. 반면 core4_lag0_certain 대조군은 칠서 행의 결측 위치만 몇 개 다르다(영천 2019-01~02 방류 결측). 이것만으로도 시드별 값이 ±0.01 달라진다. 이 차이가 바로 이 실험의 잡음 크기다.
- 1차(v1 위)에서는 난수 열 3~10개가 +0.035~+0.051 을 올렸다. C 위에서는 난수 2~5열이 −0.012~−0.019 를 내렸다. 방향은 기준 모델에 따라 다르고 크기는 비슷하다. 어느 쪽이든 ±0.02 안의 차이는 판정할 수 없다.

## 5. 선택과 종합 단계 권고

- **선택: `load2_lag0_all`(기준 미달 — 고유 효과 최대 +0.008).** 사전에 정한 규칙(CV 기준을 만족하는 변형이 없으면 고유 효과 최대)에 따른 기계적 선택이다. 이 값은 시드 잡음 안이다.
- **종합 단계 권고: P6 피처는 누적 결합 후보에서 빼는 것이 맞다.** CV 이득이 없고(부트스트랩 구간이 0 포함), 2025 9~10월 rmse_log 조건도 못 채운다. 운영 부담(영천·운문 추가 수집, 7개 호소 지점 주간 자료)도 생긴다.
- 그래도 종합 단계에서 시험하려면 아래 재사용 API 를 쓴다(선택 설정이 기본값).

## 6. 누수·2026 점검

- 전체 pytest 402개 통과(다른 실험 테스트 포함, 39초). 그중 이 실험의 누수 테스트 `tests/test_exp_r2nd_p6_damres.py` 는 29개다. 내용:
  - as_of 이후 호소 측정·댐 방류·하류 유량 행을 난수로 바꾸고 절반을 지워도, 또는 모두 지워도 5지점 × lag 0/travel × 기준일 2개에서 결과가 같다.
  - travel lag 연결은 (as_of − lag, as_of] 구간 값을 바꿔도 결과가 같다. 같은 변경이 lag 0 결과는 바꾸는 것도 확인해, 테스트가 실제로 민감하다는 것을 보였다.
  - 정의를 손 계산과 대조했다. 경과 35일 초과는 결측, 해평·강정·고령은 전부 NaN, 표 단위 생성은 행 함수와 같다.
  - 로더는 2025-12-31 이후 행을 버린다.
- 2026: 원자료는 모두 읽은 즉시 2025-12-31 이후를 버렸다. 영천·운문 수집은 2025-12-31 까지만 요청했다. 학습·평가 프레임은 `harness.load_base()` + `guard_no_2026` 를 통과했다. 2025 지표는 목표일 ≤ 2025-12-31 252행이다. `test_targets_DO_NOT_USE`·`posthoc_2026*`·`EXP-confirm/posthoc_2026*` 는 읽지 않았다. 판정 시드(FINAL_SEEDS)는 쓰지 않았다.

## 8. 한계

- 거리(지류·호소 구간)와 유속은 지도 기준 대략값이다. 이동시간은 유량과 무관한 고정값이다. 다만 lag 0 과 travel 의 차이가 없어(Δ −0.012 vs −0.011) 결론은 이 가정에 민감하지 않다.
- 남강댐 총방류량에는 사천만(가화천) 방류가 섞여 있다. 홍수기에는 남강 본류 방류를 과대 추정한다.
- 남강→칠서 연결은 측정지점(옛 위치: 칠서취수구 상류 4 km)이 남강 합류점의 상류일 수도 있어 불확실하다. 확실한 연결만 쓴 변형도 결과가 같았다.
- 호소 측정은 v1 `cell_log_t0` 와 같은 '기준일 당일 측정 포함' 규칙이다. 실제 공개 지연(채수 3일차, 2025-08 이전)은 반영하지 않았다(R2 F2 와 같은 제약).
- 해평·강정·고령에는 연결할 호소 지점이 없다. 그래서 낙동강 상류 대형 댐(안동·임하)의 호소 상태는 이 방법으로 다룰 수 없다. 다룬다면 수질측정망(R4) 호소 Chl-a 등 다른 자료가 필요하다.
- 2025 9~10월 구간은 61행이라 r2_raw 가 몇 행에 좌우된다.

## 9. 재사용 API(종합 단계)

```python
from algaecast.exp import harness as H, harness2 as H2
from algaecast.exp import r2nd_p6_damres as P6

df = H.load_base()
X = P6.build_features(df)            # 선택 설정(load2_lag0_all) 2열: dam_load_log, dam_contrib_log(같은 인덱스)
X4 = P6.build_features(df, "core4_lag0_all")   # 지시 그대로의 4열 등 다른 변형
mem = P6.members(df, seed)           # C + 선택 피처의 회귀 구성원 OOF(c1·c1_none·c1_log·c3·c2·cg·cg_*)
out = P6.builder(df, seed)           # harness2.Builder 형식 {"pred", "q90": None(v1 동결), "m_c1"...}
H2.evaluate(df, "COMBO_x", P6.builder)   # 캐시 이름은 호출 쪽 접두어로
# 다른 피처와 합칠 때: H2.c_pred(df, seed, pd.concat([X, 다른_피처], axis=1))
```

행 하나 순수 함수는 `P6.make_dam_features(algae, release, down, as_of, station_id, lag_mode="0", horizon_days=7.0, link_set="all")` 이다. 원자료 로더는 `load_reservoir_algae()`·`load_dam_release()`·`load_down_flow()` 이고, 모두 2025-12-31 이후를 버린다. 운영(일일 파이프라인)에 넣으려면 영천·운문 댐 일자료 수집(`collect/wamis_extra_dams.py` 의 END 확장)이 필요하다.
