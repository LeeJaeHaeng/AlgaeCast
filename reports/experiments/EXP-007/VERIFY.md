## 1. 2026 차단

- 코드: 새 코드 3개 파일 어디에서도 `test_targets_DO_NOT_USE`·`posthoc_2026`·test 분할을 참조하지 않는다(grep 0건). 모델 입력 프레임은 `H.load_base()` 에서 오고, `run_variant` 에서 `H.guard_no_2026(d2)` 를 거친 뒤 `H.run_members` 에 들어간다(`run_members`·`metric_row`·`leadtime` 안에서도 다시 검사한다). `build_features(guard=True)` 는 2026 행이 들어오면 멈춘다(`test_build_features_rejects_2026` 통과).
- 산출물: `chosen_oof.parquet`·`features.parquet` 는 2,566행이고, base_date 최댓값은 2025-12-29 다. 예측값이 있는 연도는 2020~2025 뿐이다.
- 원자료: 사용 측정소의 원자료에는 2026년 측정 235행이 들어 있다. 이는 계획서가 허용한 범위다. 원자료를 2025-12-31 로 잘라 지연 0 피처 26열을 2,566행 모두에서 다시 계산했고, 전체 원자료로 계산한 값과 완전히 같았다. 따라서 피처는 2026 원자료에 의존하지 않는다.
- 리드타임은 `harness.leadtime`(2025-12-31 까지의 측정)으로만 셌다.

## 2. CV 전용 선택

- `choose()` 는 `H.adoption`(CV r2_raw·CV rmse_log·리드타임)으로 걸러 `cv_r2_raw` 최댓값을 고르고, 2025 지표는 쓰지 않는다. metrics.json 의 변형 26개에 이 규칙을 독립적으로 다시 적용해도 `R4 tp_np (지연 0일)` 이 나온다. 대조군 5벌은 선택 후보에 들어 있지 않다.
- 2025 를 기준으로 골랐다면 `R4 all (지연 30일)`(2025 r2_raw 0.213)이 뽑혔을 것이다. 실제 선택 변형의 2025 값(0.155)은 v1(0.166)보다 낮다. 2025 로 맞춘 흔적은 없다.
- 계수 적합: 이 실험에서 OOF 로 적합한 값은 앙상블 NNLS 가중치뿐이다. 이 값은 `H.ensemble_expanding` 에서 연도 Y 를 Y 이전의 CV OOF 로 적합한다. 저장된 c1·c3·c2 로 앙상블을 다시 계산했고 `pred` 와 log10 최대 절대차가 0 이었다. 블록 부트스트랩은 보고용이며 선택에 쓰이지 않는다. P 분모 하한 0.001, 창 28일, 정량한계미만 0 대치는 고정값이며 튜닝하지 않았다.

## 3. 누수(as_of)

- 코드: `nutrient_features` 는 진입 직후 `cut_as_of(wq, as_of)` 를 한 번 적용한다. 이어서 ref = as_of − delay 로 `cut_as_of` 를 한 번 더 적용한다. 그 뒤의 계산(최근값·4주 평균·비율·경과일)은 이렇게 자른 프레임만 쓴다. `full_features` 는 측정소별로 묶은 원자료를 넘길 뿐 날짜를 더 걸러내지 않는다.
- 테스트: `pytest tests/test_exp_r4_nutrients.py` 를 돌려 20개가 통과했다. ruff·black 점검도 통과했다.
- 실제 원자료 직접 점검: `load_base()` 에서 지점별로 30행씩 150행을 뽑았다. 지연 0·30·60 × 대표·상류 측정소의 900건마다 다음을 비교했다.
  - (a) ref 이후 원자료를 지우고 다시 계산한 값
  - (b) ref 이후 값을 ±1e4 난수로 바꾸고, ref 이후(as_of 당일·다음 날 포함) 가짜 행을 더해 다시 계산한 값
  - 결과: 두 경우 모두 원래 피처와 같았다(불일치 0/900). ref 이전 마지막 TP 를 바꾸면 `wq_tp_last` 는 900/900 모두 바뀌었다. 따라서 이 점검은 무력하지 않다.
  - 참고: 처음 돌린 점검에서는 지연 0 에서 as_of 당일 행을 'ref 이후'로 잘못 넣어 불일치가 300건 나왔다. 이는 검증 스크립트의 오류였다. as_of 당일 행은 규칙상(≤ as_of) 포함되는 것이 맞다. 수정한 뒤 다시 돌려 위 결과를 얻었다.
- 타깃과의 관계: target_date − base_date 는 4~10일(중앙 7일)이다. 피처는 obs_date ≤ base_date 측정만 쓰므로 타깃 측정일 정보는 들어가지 않는다.

## 발견 사항(모두 경미 — 규칙 위반 아님)

1. **지연 0일 선택 변형은 '측정 당일' 값을 많이 쓴다.** 선택 변형 피처에서 `wq_days_since = 0`(base_date 당일 측정) 비율은 지점별로 다르다.
   - 강정고령 83%, 해평 71%, 물금매리 44%, 칠서 13%, 회남 6%
   - 프로젝트 규칙(`cut_as_of` 는 as_of 포함)과 계획서(지연 0 이 주 설정, 지연 30 은 민감도)에는 맞는다. 하지만 실제 공개 지연은 약 55일이다. 운영에서는 당일 TP 값을 얻을 수 없으므로 선택 변형의 CV 값은 운영 기준으로 낙관적이다.
   - 같은 묶음의 지연 60일 변형(CV 0.2110, 리드타임 18/20)과 차이가 0.0015 뿐이라 결론에는 영향이 없다. 실행자도 이 점을 적었다.
2. **선택은 잡음 수준의 차로 갈렸다.**
   - tp_np 지연 0일 0.21246, 지연 30일 0.21143, 지연 60일 0.21096, nutr_last 상류 0.21069 로 1·2위 차가 0.001 이다.
   - 이 차가 지연 0일 쪽을 고르게 했고, 그 결과 리드타임이 17/20 으로 기준선보다 1건 줄었다. 대조군 폭은 0.207~0.224 다.
   - 규칙대로 고른 것이라 위반은 아니다. 다만 이 실험의 '선택 변형'에는 특별한 의미가 없다.
3. **변형 묶음이 실행 전에 정해졌는지 확인할 수 없다.**
   - 변형 캐시 31개는 18:34~18:46 한 번의 실행에서 만들어졌다. `r4_nutrients.py` 는 그 뒤 18:50 에 수정됐다(CHOSEN 상수·보고서 문구로 보임).
   - 그보다 앞선 실행에서 `tp_np`·`p_last` 같은 작은 묶음을 결과를 보고 추가했는지는 기록이 없어 알 수 없다. 추가했더라도 CV 결과만 보고 했다면 규칙 위반은 아니고, 승자의 저주를 키우는 요인이다.
   - 현재 코드로 처음부터 다시 학습하면 보고 수치가 그대로 나온다.
4. **변형 캐시 재사용 조건이 느슨하다.** `run_variant` 는 label 과 열 이름만 같으면 캐시를 그대로 쓴다. 피처 값이나 원자료 해시는 확인하지 않는다.
   - 원자료를 다시 수집해 값이 바뀌어도 이전 결과가 쓰일 수 있다.
   - 이번 검증에서는 전체 재학습 결과가 캐시와 같아 실제 문제는 없었다. 종합 단계에서 재사용할 때는 `--fresh` 를 권한다.
5. **정량한계미만 비율 기술이 좁다.** README 의 'PO4-P 하천 측정소 약 27~37%' 는 대표 측정소 4곳(26.7~37.4%) 기준이다.
   - 상류 민감도에 쓴 측정소까지 넣으면 25~40% 다(선산 40.2%, 성주 36.9%, 삼랑진2 25.4%). 쓰지 않은 구미는 48% 다.
   - NH3-N 도 남지 9% 외에 성주 10.4%·삼랑진2 8.1% 가 있다.

## 결론

규칙(2026 차단·CV 전용 선택·as_of 누수 방지·보호 파일·수치 일치)을 모두 지켰다. 보고된 지표, 선택 결과, 채택 판정('미달')은 독립 재계산과 전체 재학습으로 그대로 재현됐다.

영양염 피처의 고유 효과가 난수 열 대조군과 구분되지 않는다는 실행자의 해석은 수치로 뒷받침된다. 선택 변형 0.2125 는 대조군 0.2074~0.2235 범위 안에 있다.

종합(EXP-011)에 넣지 않는다는 권고에 동의한다. 넣는다면 `OPERATIONAL`(지연 60일)로 넣고, 같은 열 수의 난수 대조군과 비교해야 한다.
